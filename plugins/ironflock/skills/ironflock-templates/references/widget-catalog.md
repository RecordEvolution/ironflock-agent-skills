# Widget catalog

Generated by `tools/build_widget_catalog.py` from each widget's published
`definition-schema.json` (`description` + `aiSelection`). Do not edit by hand.

Use this file to choose widgets. Then read the chosen widget's real schema with
`scripts/widget.py <package>` before writing its `chartconfig` — property names
are not listed here because they change with widget releases.

## Contents

- Data visualization: widget-linechart, widget-value, widget-gauge, widget-signal, widget-doughnut, widget-table, widget-heatmap, widget-statehistory, widget-mapbox, widget-scada
- Content and media: widget-label, widget-textbox, widget-markdown, widget-image, widget-overlay, widget-embed
- Input and control: widget-form, widget-switch, widget-filter-dropdown, widget-filter-calendar
- Navigation: widget-navbar, widget-sidenav, widget-navbutton
- Notifications: widget-toast

## Data visualization

### widget-linechart

A versatile chart widget for visualizing data as line charts, bar charts, or scatter plots. Despite the package name, this is also THE bar chart widget: set dataseries[].type to 'bar' for vertical bars and axis.orientation to 'horizontal' for horizontal ones.

**Data shape:** One or more series of (x, y) pairs. x is a timestamp, a number, or a category label and defines the position along the x-value dimension; y is the measured quantity. All series in a chart share one x dimension. An optional third column bound to data[].pivot splits a single series into one line or bar per distinct value of that column, and an optional data[].r sizes the marker for a bubble chart. Needs at least two columns of data; a single scalar has no shape to plot.

**Use when:**
- A quantity is measured repeatedly over time and the trend, shape or direction of change is the point (axis.timeseries: true, dataseries[].type: 'line').
- A quantity is compared across a handful of discrete categories — counts, totals, frequency distributions, per-machine or per-site comparisons (dataseries[].type: 'bar', axis.timeseries: false). This is the correct widget for any bar chart; there is no separate bar chart widget.
- Categories are being ranked, or their names are long enough to be unreadable side by side under a vertical axis (dataseries[].type: 'bar', axis.orientation: 'horizontal').
- Two numeric variables are being correlated as a cloud of individual points (dataseries[].type: 'scatter'), optionally with data[].r encoding a third variable as marker size.
- Several quantities with different units or wildly different ranges belong on one chart (assign the second group dataseries[].yAxis: 'right').
- The same measurement is broken down by an entity — one line per machine, per site, per program (bind the breakdown column to data[].pivot).

**Not for:**
- Parts of a whole, shares, or percentages that add up to 100% — use widget-doughnut.
- A single current number, reading or KPI with no second dimension to plot — use widget-value, or widget-gauge when it should be read against a min/max range.
- Records the user needs to read row by row, or data with more columns than an x and a y — use widget-table.
- Intensity or density across two categorical dimensions at once, i.e. a matrix or calendar grid — use widget-heatmap.
- How long an entity stayed in each discrete state over time (state timelines, machine mode history, up/down periods drawn as spans). A bar chart of state durations is the wrong shape — use widget-statehistory.
- Anything positioned by geographic coordinates — use widget-mapbox.
- A single binary or few-valued status shown as an indicator rather than plotted — use widget-signal, or widget-switch when the user must also be able to toggle it.
- Free text, headings or explanatory prose — use widget-label, widget-textbox or widget-markdown.

### widget-value

A simple numeric value display widget for showing key metrics with labels and units. Use this widget to prominently display important numbers like sensor readings, KPIs, or any scalar value that already exists in the data — the widget performs NO aggregation (no count/sum/avg; the only reduction is averaging the latest N readings via advanced.averageLatest).

**Data shape:** One number per entry: dataseries[].data[].value, with an optional timestamp for freshness checks (advanced.maxLatency) and averaging over the latest N readings. Label, unit and decimal precision are set per entry. A pivot column produces one readout per distinct value. The subtitle can be bound as well, and shown as a local date and time when it holds a timestamp (subTitleType).

**Use when:**
- A single current figure is the whole point — a KPI tile showing a latest reading or an already-computed count/total that exists as a value in the data.
- The number has a unit and a sensible precision and should be read exactly.
- One tile per machine or site should be generated from a single column (data[].pivot).
- Stale data should be visibly flagged rather than shown as current (advanced.maxLatency).

**Not for:**
- Counting or aggregating rows — the widget performs NO aggregation (no count/sum/avg); it displays a value that already exists in the data or is embedded as a static number.
- A number that only means something against a minimum and maximum — use widget-gauge.
- How the number is changing — use widget-linechart.
- Its share of a total — use widget-doughnut.
- Several fields per entity that belong side by side — use widget-table.
- Text rather than a figure — use widget-label.

### widget-gauge

A circular gauge widget for displaying single numeric values within a defined range. Use this widget to show KPIs, sensor readings, progress indicators, or any metric that benefits from a visual representation against minimum and maximum boundaries.

**Data shape:** One number per gauge together with the bounds it is read against: dataseries[].data[].value, with sections.gaugeMinValue and sections.sectionLimits[] defining the coloured zones. Optionally a timestamp for freshness and a pivot column producing one gauge per distinct value.

**Use when:**
- A current measurement is only meaningful against a range — a tank at 60% of capacity, a temperature inside or outside its safe band, utilisation against 100%.
- Zones matter: normal, warning and critical should be visible as colour without reading the number.
- One gauge per machine or site should be generated from one column (bind it to data[].pivot).

**Not for:**
- A number with no natural minimum and maximum — a total, a count, a price. Use widget-value; an invented range makes the dial meaningless.
- How the value got here or where it is heading — a gauge shows only the latest point. Use widget-linechart.
- A share of a total — use widget-doughnut.
- A tank, pump, valve or other industrial asset that should be drawn as itself rather than as a dial — use widget-scada.
- A binary condition — use widget-signal, or widget-switch when it must also be controllable.

### widget-signal

A signal indicator widget for displaying status using colored shapes. Use this widget to show binary or multi-state status indicators like online/offline, OK/warning/error, or any condition that maps to visual states.

**Data shape:** One value per signal, each with a colorMap[] of comparison conditions deciding which colour its shape takes. Display-only. Several signals can be laid out horizontally or vertically as circles or squares.

**Use when:**
- A condition should be recognisable at a glance as a coloured dot — online or offline, OK / warning / error, connected, in alarm.
- Several such indicators belong together as a status panel.
- The mapping from value to colour needs conditions rather than exact matches (thresholds, ranges).

**Not for:**
- An indicator the user must also be able to switch — use widget-switch; this widget is display-only.
- The number behind the status — use widget-value, or widget-gauge to show it against a range.
- How long it has been in that state, or when it last changed — use widget-statehistory.
- An industrial asset that should look like itself — use widget-scada.
- A one-off event announcement rather than a standing condition — use widget-toast.

### widget-doughnut

A doughnut/pie chart widget for visualizing proportional data as circular segments. Use this widget to display part-to-whole relationships, such as market share percentages, budget allocations, or category distributions.

**Data shape:** A list of named parts with one numeric size each: dataseries[].sections[] gives a label and a value per slice. The parts are drawn as shares of their common total, so the numbers must be summable quantities (counts, amounts, durations) rather than rates or averages. An optional column bound to sections[].pivot splits the data into several rings, one per distinct value. Reads best with 2-8 slices.

**Use when:**
- The question is what share each category has of a whole — split of production by program, share of downtime by cause, market share, budget allocation.
- The numbers are parts of one total and the proportions matter more than the absolute values.
- A pie chart is asked for rather than a doughnut: same widget, set dataseries[].settings.cutout to '0%'.
- One ring per machine, site or period should be generated from a single column (bind it to sections[].pivot).

**Not for:**
- Comparing magnitudes across categories that are not shares of a total, or where there are more than about eight of them — use widget-linechart with dataseries[].type: 'bar'. Bars compare lengths, which the eye judges far better than angles.
- Anything changing over time — a doughnut has no time dimension. Use widget-linechart.
- A single value read against a minimum and maximum — use widget-gauge; a doughnut of one slice is always 100%.
- Reading exact numbers rather than proportions — use widget-table, or a bar chart with dataseries[].styling.showValueLabels enabled.

### widget-table

A data table widget for displaying structured information in rows and columns. Use this widget to present lists, records, or any tabular data with customizable column types and formatting.

**Data shape:** Rows and columns. Each columns[] entry binds one column of the source data and declares how to render it — string, number with precision, timestamp with format, boolean, state with a colour map, image, or a clickable button with a link. The row count is whatever the query returns.

**Use when:**
- The user needs to read individual records — event logs, device inventories, order lists, alarm histories.
- More than two or three fields per row matter, so no chart can carry them all.
- Exact values matter more than trends or comparisons.
- Each row should offer a link or action of its own (a column of type 'button').

**Not for:**
- Spotting a trend, comparing magnitudes, or seeing a distribution — use widget-linechart; a table makes the reader do the work a chart does for them.
- One number that matters more than the rest — use widget-value, or widget-gauge to read it against a range.
- Shares of a total — use widget-doughnut.
- Text written by hand rather than queried — use widget-markdown.

### widget-heatmap

A heatmap chart widget for visualizing data intensity across two categorical or ordinal dimensions. Use this widget to display patterns in data such as activity over time, correlation matrices, geographic data density, or any metric that varies across two axes.

**Data shape:** Triples of (x, y, heat) in dataseries[].data[]: two categorical or ordinal coordinates and one numeric intensity at their intersection. It is a matrix, not a series — it needs values spread across both dimensions to be worth drawing.

**Use when:**
- Something varies across two dimensions at once and the pattern is the point — hour of day against day of week, machine against shift, sensor against location.
- A correlation matrix, a density grid, or a calendar-style view of activity is wanted.
- Clusters and outliers should stand out by colour rather than being read off an axis.

**Not for:**
- One dimension against a measured value — use widget-linechart; a single-row heatmap is harder to read than a bar chart.
- Which state something was in over time, drawn as spans — use widget-statehistory.
- Density over a geographic area — use widget-mapbox with dataseries[].type: 'heatmap'.
- Exact values that must be read rather than compared — use widget-table, or enable heatMap.showValues if the grid is small.

### widget-statehistory

A state history timeline chart widget for visualizing discrete state changes over time. Use this widget to display how entities transition between states (e.g., machine operating states, device connectivity, task status).

**Data shape:** State-over-time rows: dataseries[].data[] entries of (tsp, state, label), where state is a discrete name matched against stateMap[] for its colour and label identifies the entity. Each entity becomes a row of coloured spans along a shared time axis. A pivot column can generate the entities.

**Use when:**
- The question is what state something was in, and for how long — machine mode, running / idle / fault, connectivity, job status.
- Several assets should be compared as rows on one timeline to reveal overlaps, gaps and simultaneous stoppages.
- Uptime, downtime reasons or shift patterns should be visible as durations rather than counted.

**Not for:**
- A numeric measurement over time — use widget-linechart; this widget plots state names, not quantities.
- How often each state occurred, or total time per state as a comparison — aggregate first, then use widget-linechart with dataseries[].type: 'bar', or widget-doughnut for shares of total time.
- Only the current state — use widget-signal, or widget-switch when it must be controllable.
- Two categorical dimensions with a numeric intensity — use widget-heatmap.

### widget-mapbox

A Mapbox-powered geospatial visualization widget for displaying location-based data on interactive maps. Use this widget for GPS tracking, asset locations, geographic heatmaps, route visualization, or any data with latitude/longitude coordinates.

**Data shape:** Points carrying coordinates: dataseries[].data[] entries with lon and lat, optionally alt and a numeric value, rendered as circles, icons, a density heatmap or connected lines. A pivot column produces one layer per distinct value.

**Use when:**
- Position on the earth is the point — vehicle and asset locations, site maps, field service, GPS traces.
- A route or track should be drawn by connecting points in order (dataseries[].type: 'line').
- Density across an area should be shaded (dataseries[].type: 'heatmap').
- The view should keep following the latest position (follow: true).

**Not for:**
- Coordinates that are only incidental, where the real question is a measured value over time — use widget-linechart.
- Positions on a floor plan, schematic or photo rather than on the earth — use widget-overlay.
- Distance, speed or dwell time presented as numbers — use widget-value or widget-table.
- How long an asset stayed in each place or state — use widget-statehistory.

### widget-scada

A SCADA symbol widget that renders interactive industrial SVG symbols from the ThingsBoard SCADA library. Select a symbol type and configure its appearance, data bindings, and behavior.

**Data shape:** One industrial symbol chosen from a fixed library (tanks, pipes, valves, pumps, meters, breakers, generators, panels), with bindings mapping live values and boolean conditions onto its appearance — fill level, flow direction and speed, running or stopped, opened or closed, warning, critical, leak — plus optional device actions on click.

**Use when:**
- A physical asset should be drawn as itself: a tank that fills, a valve that opens, a pump that runs, a pipe that shows flow direction.
- A process diagram is being assembled from standard components, one widget per component.
- State should be legible as animation and colour — flowing, stopped, leaking, in alarm — rather than as a number.
- Clicking the symbol should command the underlying device (actions).

**Not for:**
- An asset with no matching symbol in the library — annotate a picture of it with widget-overlay instead.
- A bounded reading that only needs a dial — use widget-gauge.
- A plain on/off indicator with no industrial meaning — use widget-signal, or widget-switch when it must be toggled.
- The history of the asset's values or states — use widget-linechart or widget-statehistory.

## Content and media

### widget-label

A lightweight label widget for displaying a single configurable text string. Use this widget for headings, captions, status indicators, KPI labels, or any place a dashboard needs simple styled text.

**Data shape:** A single text string, static or bound to one data value, plus typography and background styling. No series and no records.

**Use when:**
- A dashboard needs a heading, caption, section title or short standing note.
- One short data-driven string should be shown prominently — a current mode, an operator name, a status word.
- Styling must be controlled directly (size, weight, alignment, colour, background) without writing markup.

**Not for:**
- A number that deserves emphasis with a unit and a precision — use widget-value.
- Several paragraphs, or a title / subtitle / body structure — use widget-textbox.
- Lists, links, tables, code or any markup, or prose interpolating several live values — use widget-markdown.
- A short-lived message announcing that something just happened — use widget-toast.

### widget-textbox

A rich text display widget with three configurable sections: title, subtitle, and body. Use this widget for displaying formatted text content with full control over typography and colors.

**Data shape:** Three independently styled text sections — title, subTitle and body — each either static or bound to a data value. The body accepts multi-line text. No markup is interpreted.

**Use when:**
- A panel needs a heading, a subheading and body text with typography controlled per section.
- An information block, description or status message should be styled without writing Markdown.
- The text is partly static and partly data-driven, and the sections should be coloured or sized differently.

**Not for:**
- One line of text — use widget-label.
- Markup: lists, links, tables, code, or several interpolated values in running prose — use widget-markdown.
- Numbers that should read as figures with units — use widget-value.
- A transient message about something that just happened — use widget-toast.

### widget-markdown

A markdown rendering widget for displaying formatted text with dynamic variable substitution. Use this widget for documentation, instructions, dynamic reports, or any rich text content on dashboards.

**Data shape:** A Markdown document, with {{variableName}} placeholders substituted from data[] entries that each bind a label to a live value.

**Use when:**
- Prose, documentation, instructions or a written summary belongs on the dashboard.
- The text needs structure or markup — headings, lists, links, tables, code blocks.
- A narrative should incorporate live numbers, e.g. 'Line 3 produced {{units}} units today'.

**Not for:**
- A single styled string with no markup — use widget-label; a Markdown renderer is overkill.
- Fixed title / subtitle / body sections with per-section typography — use widget-textbox.
- Tabular data coming from a query rather than written by hand — use widget-table.
- Numbers that should be read as figures rather than embedded in a sentence — use widget-value.

### widget-image

An image display widget for showing single or multiple images from URLs or base64-encoded data. Use this widget to display photos, diagrams, camera feeds, or any visual content on dashboards.

**Data shape:** Image sources only: one imageUrl or uploaded file, or a list of data[] entries each with an imageUrl, an optional label and an optional timestamp for time-range filtering. Nothing numeric is plotted.

**Use when:**
- Photos, camera stills, diagrams, product shots or scans should be shown as they are.
- A set of images should fill the tile as a responsive grid, optionally labelled (multiImage: true).
- Images should follow the dashboard's selected time range through their timestamp.

**Not for:**
- An image that needs live values drawn on top of it — a floor plan with readings, a schematic with fill levels. Use widget-overlay.
- A live web page rather than a picture — use widget-embed.
- An icon conveying status — use widget-signal, or widget-scada for an industrial symbol.
- Images belonging to individual records alongside other fields — use widget-table with a column of type 'image'.

### widget-overlay

An image overlay widget for displaying data-driven annotations on top of background images. Use this widget to create visual dashboards that combine a schematic, floor plan, process diagram, or photo with real-time data overlays.

**Data shape:** A background image plus pins placed on it by relative coordinates (relXPos / relYPos in 0-1, so they scale with the image). Each pin binds one live value, drawn either as a progress bar (progressPins) or as text (textPins).

**Use when:**
- Values only make sense in their spatial context — tank levels on a process diagram, room temperatures on a floor plan, station output on a line layout.
- A photo or schematic already exists and should be annotated with live readings.
- Fill levels should be shown in place as progress bars against a picture of the plant.

**Not for:**
- Positions on the earth rather than on a picture — use widget-mapbox.
- A standard industrial component (tank, pump, valve, meter) that the platform can already draw and animate — use widget-scada, which needs no background image.
- An image with no data on it — use widget-image.
- Values compared against each other rather than placed in space — use widget-linechart, widget-value or widget-gauge.

### widget-embed

An iframe embed widget for displaying external web content within the dashboard. Use this widget to integrate third-party dashboards, documentation, external tools, or any web-accessible content.

**Data shape:** URLs of external web pages, and nothing else: either one static webUrl, or a list of {url, title} entries in data[] for a grid of several embeds. No measurement column is bound and nothing is plotted.

**Use when:**
- An existing web page, third-party dashboard, documentation site or internal tool should appear inside the dashboard instead of being rebuilt.
- The content is served by another system and is already visual — a Grafana board, a camera web UI, a report page.
- Several such pages should sit side by side in a responsive grid (multiEmbed: true).

**Not for:**
- Data held in the platform's own tables — build the visualization natively so it themes, filters and refreshes with the rest of the dashboard (widget-linechart, widget-table, widget-value and so on).
- A static image or a camera still — use widget-image; an iframe is much heavier and many image hosts refuse to be framed.
- Formatted text or a written report — use widget-markdown.
- Pages that refuse framing. Most sites set X-Frame-Options or frame-ancestors and will show blank; this cannot be worked around from the config, so link to them with widget-navbutton instead.

## Input and control

### widget-form

A form widget for collecting user input and storing it in database tables. Use this widget to create data entry interfaces for manual input, configuration settings, user feedback, or any scenario requiring structured data collection.

**Data shape:** Writes rather than reads. Each formFields[] entry maps one input control to a database column through targetColumn, and submitting stores a row. Field types cover text, number, dropdown, checkbox, textarea and datetime, with validation, required flags, defaults and conditional visibility.

**Use when:**
- A person needs to enter or correct data that is then persisted — manual readings, maintenance notes, quality checks, configuration values, feedback.
- Input must be structured and validated, with required fields, defaults, or fields that appear only when another field has a given value (conditionalDisplay).
- Records should also be deletable or flagged as deleted from the dashboard (deleteButton, deleteFlagColumn).

**Not for:**
- Narrowing what other widgets display — that is filtering, not data entry. Use widget-filter-dropdown or widget-filter-calendar.
- Sending a command to a device rather than storing a value — use widget-switch, or widget-scada for an industrial symbol with actions.
- Showing stored records back to the user — use widget-table.
- A single button that only navigates somewhere — use widget-navbutton.

### widget-switch

A toggle switch widget for displaying and controlling binary device states. Use this widget to show ON/OFF status indicators that can also trigger device actions when clicked.

**Data shape:** One value per switch, interpreted as ON or OFF through stateMap, plus an optional device or app action and topic fired on click. Both displays and controls.

**Use when:**
- A binary device state should be shown and changed from the dashboard — a pump, a light, a valve, an enable flag.
- An operator needs a control, not only a readout.
- Several related toggles belong together in one control panel.

**Not for:**
- A status the user must not be able to change — use widget-signal, which is display-only.
- More than two states — use widget-signal for the indicator, or widget-scada for an industrial symbol.
- Values that are entered and stored rather than commanded — use widget-form.
- The history of the switching — use widget-statehistory.
- A tank, valve or pump that should be drawn as itself and animated — use widget-scada.

### widget-filter-dropdown

A dropdown filter widget for selecting values from a predefined list. Use this widget to allow users to filter dashboard data by categorical values such as device names, locations, status types, or any enumerable options.

**Data shape:** A fixed list of {label, value} options defined in the config. It writes the selected value into the URL parameter named by parameterKey; each consuming widget needs its own filterAnd condition with useFilter: true on the relevant column.

**Use when:**
- The user should switch the whole dashboard between subsets of one categorical dimension — machine, site, line, product, status.
- The set of choices is known and stable enough to be listed in the configuration.

**Not for:**
- Choosing a time range or a date — use widget-filter-calendar.
- Capturing a value that must be stored — a filter only narrows what is displayed and writes nothing back. Use widget-form.
- Options that have to be discovered from the data at runtime; this list is static configuration.
- Triggering a device action or command — use widget-switch, or widget-scada for an industrial symbol.

### widget-filter-calendar

A date/time range picker filter widget using Flatpickr calendar. Use this widget to allow users to select date ranges for filtering dashboard data.

**Data shape:** No data input at all. It writes the chosen start and end timestamps (epoch milliseconds) into the URL parameters named by startKey and endKey; other widgets read those names through their own query parameters.

**Use when:**
- The user must choose the time range that the rest of the dashboard shows.
- A single date rather than a range is wanted — configure only startKey or only endKey.
- A report or historical analysis needs an adjustable period instead of a fixed rolling window.

**Not for:**
- Filtering by a category, device, site or status — use widget-filter-dropdown.
- Displaying a date rather than choosing one — use widget-value or widget-label.
- Capturing a date that must be stored — a filter only narrows what is displayed and writes nothing back. Use widget-form with a field of type 'datetime'.
- Pinning the dashboard to a rolling window such as 'the last 24 hours' with no user control — that is each consuming widget's own sliding-window setting and needs no filter widget at all.
- Note that adding this widget alone changes nothing: every widget meant to follow it must bind timeStartParam/timeEndParam to these key names AND have a complete sliding time window configured, or the chosen range is discarded.

## Navigation

### widget-navbar

A horizontal navigation bar widget for creating top-level dashboard navigation. Use this widget to provide consistent navigation across dashboard pages with a clickable title and multiple navigation items.

**Data shape:** Navigation structure only: a title with a route, plus navItems[] each carrying a label, an icon and a route. No data input.

**Use when:**
- A multi-page dashboard needs consistent top-level navigation across its pages.
- A header combining branding (the title) with links to the main sections is wanted.
- Route parameters should be carried along per item (variables[]).

**Not for:**
- Navigation down the side of the page — use widget-sidenav.
- A single link or call to action — use widget-navbutton.
- Switching what data the page shows rather than which page is shown — that is filtering. Use widget-filter-dropdown.
- A heading that is only text and does not navigate — use widget-label.

### widget-sidenav

A vertical side navigation widget for creating sidebar menus in dashboards. Use this widget to provide hierarchical or list-based navigation along the side of the dashboard.

**Data shape:** Navigation structure only: a title with a route, plus navItems[] each carrying a label, an icon and a route. No data input.

**Use when:**
- A dashboard has enough sections to need a persistent menu that does not consume header height.
- Navigation should sit down the side, list-style, alongside the content.
- An application-like layout with settings or sub-sections is being built.

**Not for:**
- Navigation across the top of the page — use widget-navbar.
- A single link or button — use widget-navbutton.
- Choosing which data is shown rather than which page — use widget-filter-dropdown.
- A heading that is only text and does not navigate — use widget-label.

### widget-navbutton

A navigation button widget for in-dashboard navigation between pages or sections. Use this widget to create clickable buttons that navigate users to different dashboard views, external pages, or perform back navigation.

**Data shape:** A single destination: a label, an icon and a route, plus optional route variables. No data input.

**Use when:**
- One clickable element should take the user somewhere — a detail page, an external site, or back.
- A call to action belongs next to specific content rather than in a navigation menu.

**Not for:**
- Several destinations that belong together as a menu — use widget-navbar or widget-sidenav.
- A button that writes or submits data — use widget-form.
- A button that commands a device — use widget-switch, or widget-scada for an industrial symbol.
- Per-row links inside a list of records — use widget-table with a column of type 'button'.

## Notifications

### widget-toast

A transient toast / notification widget. The backend publishes rows into a data-backend table; bind the message and severity columns of that table to this widget, and each newly published row pops up a short-lived toast inside the widget tile.

**Data shape:** Newly published rows of a backend table. The message text and a severity (success / error / info / warning) are data-driven, and each new row pops up a short-lived notification inside the tile. Display time, position, stacking limit and colours are static configuration.

**Use when:**
- Events should announce themselves as they happen — a job finished, a batch failed, a threshold was crossed.
- The dashboard should react visibly to newly published rows without the user watching a list.
- Severity should be conveyed by colour and icon for a moment rather than kept on screen.

**Not for:**
- A message that must remain readable — toasts disappear after displayTime. Use widget-label, widget-textbox or widget-markdown.
- The history of what happened, browsable after the fact — use widget-table.
- A standing condition rather than an event — use widget-signal.
- How often events occur, or their distribution — use widget-linechart with dataseries[].type: 'bar'.
